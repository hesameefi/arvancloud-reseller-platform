# ZarinPal Merchant Dashboard

Merchant-facing analytics platform: classical BI (ClickHouse rollups, peer ranking, drill-down), an agentic insight layer with grounded LLM narratives, and a conversational “Ask the Dashboard” agent that answers only from computed `AnalysisResult`s. Django + DRF, React, PostgreSQL, ClickHouse, Temporal, Redis, and AvalAI.

## Quickstart

```bash
cp .env.example .env
docker compose up
```

That starts Postgres, ClickHouse, Redis, and Temporal (`temporalio/auto-setup` with its own Postgres). Application services (`api`, `frontend`, `ingestion`) are Compose stanzas with the `app` profile and land in later sprints. Chat is not a Compose service — turn handling lives in `api`; memory consolidation lives in `temporal-worker`.

Engineering spec: [docs/spec.md](docs/spec.md).

# ZarinPal Smart Merchant Copilot

An explainable merchant-intelligence dashboard for the ZarinPal Analytical Challenge. It turns more than 2.2 million payment-attempt rows into session-aware revenue leakage, peer benchmarks, and routing opportunities—while exposing the exact DuckDB SQL and population behind every result.

## Strategic value

Merchants need decisions, not a wall of payment logs. The Copilot distinguishes checkout abandonment from payment-attempt failure, measures opportunity in IRR or Toman, finds unusual failure windows, and translates evidence into a prioritized recovery action. Sensitive `adjusted_fee` data is used only as a scaled **relative fee index**, never as ZarinPal's actual fee or rate.

The app is designed around three modules:

- **Revenue Leakage Engine:** session funnel, PSP-associated failure spikes, hourly leakage, and recovery playbooks.
- **Benchmarking & Segmentation:** fair merchant percentiles, ticket-size bands, and PSP conversion comparisons.
- **Smart Fee & Payment Routing:** relative fee performance and high-volume-window opportunities.
